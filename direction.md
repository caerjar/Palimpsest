# Direction — palimpsest

_Named 2026-08-30 during the direction triage. Revisit when the kill condition fires or first contact happens._

## Who it's for

**Me, for this cycle.** `[established]` — emu-butch is live in it today, which
is the strongest evidence of real use anywhere in this stack.

"Other writers with manuscripts" was the first answer, but the kill condition and
first contact both scoped it to one book and one person. Recorded as the later
ambition it is: `[speculative]`.

## What they do today instead

Scrivener, Word, or Obsidian. For the specific thing palimpsest does — a folder of numbered sections becoming an editorial dossier you edit in the browser — there is no incumbent.

## The one job

**Turn a folder of numbered markdown sections into an editorial dossier you can edit in the browser.**

## Kill condition

**I finish emu-butch and stop opening it.**

Observable, likely, and honest: tools built around one book often end with it.
That is not failure, it is the shape of the thing.

## First contact

**None this cycle. It stays mine until emu-butch is done.**

A deliberate deferral, not an oversight.

**Prerequisite before any writer touches it:** the `reading-copy` tool writes git
tree objects directly and produces corrupt commits — duplicate tree entries and
silently dropped files. On 2026-08-30 it cost the researcher vault 24 files across
three commits, repaired only because the damage was noticed by accident. Handing
that to someone else's manuscript would be worse than not shipping.

## Open

- **The reading-copy git bug is unfixed at source.** It will corrupt again on its
  next save. This is the single most important open item in the project.
- Whether "book-agnostic" is true has never been tested — one book has ever been
  in it.
