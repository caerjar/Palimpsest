Help — using __PAL_TITLE__

Palimpsest turns a folder of numbered Markdown sections into an editorial workbench you edit in the browser, then export. It also plays your writing like a musical score.

Getting started

A book is a folder of sections. Open the Library (top bar) to create a new book, import one, switch between books, or remove one.

  • New book: Library → “Start a new book”, give it a title. It opens with one starter section.
  • Import: Library → “Import a manuscript” — upload a PDF or Word file, or pick a folder of .md files. See Import.
  • The top bar is the same on every page: the book title (→ reading copy), the menus, and ⤓ Export / ↻ Rebuild on the right.

Writing & editing

The Reading copy is home — every section in reading order.

  • Edit a section: click ✎ edit under it, type, then it saves to disk automatically (and, when your book is in a git repo, commits — so ⧗ history can show and restore past versions).
  • Search & filter: the search box and the chips at the top isolate sections by word, motif, or label.

Sections

  • Add / insert: ＋ section (bottom-left) adds one at the end; ＋ insert below under a section inserts after it.
  • Reorder: drag the ⠿ handle.
  • Set aside: ⇥ set aside parks a section out of the flow (kept on disk, shown in the “Set aside” shelf).
  • Delete: 🗑 delete archives a section to manuscript/_attic/ — reversible.

Labels & parts

  • Labels: click + label on a section to tag it; labels become filter chips and a colored dimension.
  • Parts: use the Parts board to group sections into parts / chapters.

Index (watchlist)

The Index is your back-of-book watchlist. Add a term (with optional aliases) and it lists every section where the word appears, found by searching the text. Add and remove terms right on the page; a term you add shows immediately (with a 0 count until the word turns up in your writing).

Motifs

A motif is a thread you name — a word or an idea that keeps coming back. On the Motifs page, give it a name and a colour, then type a word and press find: every section containing that word is added, and you can adjust the list by hand. The reading copy then shows each motif as a chip and colours the spine of every section it appears in. Nothing is inferred — the search only finds a word you chose.

Copyedit review

The Copyedit review shows each section as original (left) vs. a suggested edit (right), with word-level highlighting. Edit on the right, save to write it back, mark done to finish. Suggestions live in manuscript-suggestions/ and are yours to fill in — nothing is generated.

Edit board

The Edit board is a revision checklist. Add columns and items in the page; tick them off as you work. Both the checklist and your ticks save to the book.

Export

Top bar → ⤓ Export:

  • Markdown and Web page (HTML) — always available, no tools needed.
  • Word (.docx) — needs pandoc.
  • PDF — needs pandoc + XeLaTeX.

Running in Docker, all four work out of the box. The menu greys out a format whose tool isn't installed.

Import

Library → “Import a manuscript”. A PDF splits by chapter (its bookmarks) or by page; a Word file splits at headings; a Markdown folder becomes one section per file. Each import creates a new book.

  • Markdown folder — no tools needed.
  • Word (.docx) — needs pandoc.
  • PDF — needs PyMuPDF, which has to be installed into the same environment Palimpsest runs from; a pip install in a different Python won't be found. If it's missing, the import says so and prints the exact command for your install.

Running in Docker, all three work out of the box.

Managing books

  • Switch / open: click a book in the Library.
  • Remove: the ✕ on a book card moves it to .trash/ in your workbench (recoverable — move it back to restore). You can't delete the book that's currently open.
  • Where books live: shown at the bottom of the Library; change it with pal home <folder>.

Privacy & access

  • Nothing leaves your machine. No accounts, no network calls, no AI. The server binds to localhost by default (in Docker the port is published to localhost too), and whatever it is bound to, it refuses requests that come from another site or that arrive addressed to another hostname — so a page you have open in another tab can't reach your book.
  • There is no password. Anything that can reach the port can edit the book, which is exactly why it stays on localhost. If you deliberately publish it (a reverse proxy, a different Docker ports: line), name that hostname in PAL_ALLOWED_HOSTS — and put your own authentication in front of it.
  • The writing record keeps keystrokes. The Writing record page logs your typing to dossier/keystrokes/*.jsonl — a plain-text record of what you typed and when. Palimpsest never commits it (saves only stage the manuscript and your authored files), and a new book's .gitignore excludes dossier/ so your own commits skip it too. It stays on this machine, but it is readable by anything that can read the folder; delete the files to clear it.
  • A book folder is executable content in one sense: its book.toml decides which directories are read and written, and can supply a LaTeX header used when exporting a PDF. Palimpsest warns on startup when a book points outside its own folder, and refuses a LaTeX header from outside it. Treat a book someone sent you the way you'd treat any other file from them.

Tips

  • ↻ Rebuild regenerates the reading pages from your latest edits — use it if a page looks stale. It never changes your writing.
  • The little built HH:MM stamp (bottom-left) tells you when the page was generated; reload if it looks old.
  • These editing controls only work when the app is served (pal serve or the Docker app). Opened as a plain file, pages are read-only.
